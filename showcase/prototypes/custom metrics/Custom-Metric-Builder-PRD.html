1Scope

The Custom Metric Builder redesigns how analysts create custom metrics. Today’s editor uses an unclear syntax, gives no inline guidance, and shows one generic error. This turns it into a guided, token-based editor with a searchable reference panel, real-time validation, and AI assistance.

In scope

  • A modal formula editor that renders the formula as colour-coded tokens.
  • Two ways to build: typing (autocomplete + inline recommendations) and the option-selector (clicking the reference panel).
  • Reference panel: Fields / Operators / Formulas, with search, hover-to-preview, click-to-insert.
  • Preset formulas that insert with empty slots to fill (TRIF Rate, Injury Rate %, Incident Count).
  • Real-time validation with a clear message; Save blocked while invalid.
  • AI Assist: a single editable prompt that returns an editable formula, with feedback and revert.
  • Paste a JavaScript-style formula and have it parse into tokens.

Out of scope ✕ Dropped from ticket

  • Live numeric preview (value + step-by-step breakdown). The widget updates on Save, so a preview adds complexity for little value.
  • Metric Name & Colour inside this modal — they stay in the widget-settings rail. The modal is formula-only.

2Key decisions

DecisionResolution
Operator syntaxUse JavaScript operators == != > >= < <= && || and + - * /. Replaces IN / NOT IN.✎
PlacementLighter centered modal; formula-only.✎
Two build modesTyping → inline dropdowns; clicking → cycles the panel tabs. Last action wins.+
Chips vs badgesChips (outline) only for interactable tokens; badges (filled) are display-only.+
Live previewDropped.✕
Reset vs DiscardOne field button: Reset (clear) for new metrics; Discard (revert to saved) when editing.+
ValidationOne plain-language message under the field (not boxed, no auto-fix yet).✎
Needs dev sign-off: replacing IN/NOT IN with ==/!= breaks the “stay consistent with current operators” line — existing formulas need a migration mapping (see §6).

6Technical

Operators → JavaScript

TokenMaps toGroupNotes
== !=== / != (or “contains” on multi-select)ComparisonOn multi-select fields, == means “contains”.
> >= < <=sameComparisonNumeric fields.
&& ||&& / ||LogicalReplaces AND / OR.
+ - * /sameArithmeticDivide-by-zero → “no result”.
( )sameGrouping—
  • Tokens have a kind (field / operator / value / hours / slot) + an “unknown” flag; Save stores the ordered token list (parseable from / serializable to a string).
  • Custom metrics always return a single numeric value (count or number derived from counts) — no boolean/if-else return.
  • {Hours} pulls Location Hours for the selected location (+ sub-locations when the toggle is on); must match current system logic.
  • Suggestions respect data-access permissions; validation runs in real time and must stay responsive on 800+ field forms.
  • AI must use only valid fields/operators and fail gracefully (no fabricated fields).
  • Migration (4.9): existing metrics migrate to tokens with unchanged calculations; rollback must exist; treat as backend, surface UI only if a metric actually changes.

Field descriptions (by type)

TypeDescription
CheckboxCounts completed forms where the options you pick were selected.
DropdownCounts completed forms where the option you pick was selected.
TextCounts completed forms whose text contains the value(s) you pick. If it holds numbers, it adds them all up instead.
Likert scaleCounts completed forms where the statement you pick got one of the responses you choose.
System — {Hours}Pulls in the hours for the location (and sub-locations, if turned on) selected on the dashboard.

Operators

OpNameDescription
+AddAdds two numbers together. Handy for combining counts into one total.
-SubtractTakes the second number away from the first.
*MultiplyMultiplies two numbers. Often used to scale a count, like × 200,000 for safety rates.
/DivideDivides the first number by the second. Dividing by zero shows no result.
==Equal toCounts forms where the field matches the answer you pick.
!=Not equal toCounts forms where the field is anything other than the answer you pick.
> >= < <=Greater / less thanKeeps forms where the number is above / at-or-above / below / at-or-below the value you set.
&&AndBoth conditions must be true for a form to be counted.
||OrEither condition can be true for a form to be counted.
( )GroupGroups part of a formula so it runs first.

8Open questions

  • IN → ==: confirm the operator change with dev + define the migration mapping for existing formulas.
  • Multi-select semantics: confirm the “contains” behaviour and wording for == / != on multi-select checkbox & dropdown fields.
  • Likert: a scale has multiple statements, each rated — prototype simplifies to a single response set. Statement picker needed?
  • Preset slots: presets make both field and value empty — should some keep a fixed value (e.g. TRIF always “== Yes”)?
  • Auto-fix: build auto-fix suggestions, or rely on the clear message alone?
  • Numeric vs Text field grouping (currently folded together).

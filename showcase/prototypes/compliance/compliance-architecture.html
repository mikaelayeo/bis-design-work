Setup & Daily Use Flow

Recommended order of operations. Steps 1–6 are initial setup. Steps 7–8 are ongoing operations.

Initial Setup
1
Define Worksites
Map your portal locations to compliance worksites, or create custom worksites that group multiple locations together.
Map LocationsCustom Worksite
2
Define Asset Groups
Map asset categories to compliance groups, or create custom groups with assets from multiple categories.
Map CategoriesCustom Group

Configure Settings
Set up requirement types (GOV, HAZ, TRN...) and control measure types (Policy, Procedure, Training...). Customize for your industry.
Req. TypesMeasure Types
4
Create Requirements
Build your compliance requirements. Assign owners, scope to locations/assets, and add control measures that map to your portal content.
Name & Describe Assign Owner Add Measures Map Content
5
Create Frameworks
Create compliance frameworks (starts as Inactive). Map worksites and asset groups. Select which requirements apply.
New Framework Map Sites Map Assets Add Requirements
6
Activate Framework
When ready, activate the framework. The system begins testing control measures and surfacing compliance status on the dashboard.
Activate Tests Begin
Ongoing Operations
7
Monitor Dashboard
View compliance status across all active frameworks. Pie charts show passing, failing, and unaddressed requirements. Check your personal remediation tasks.
Review Status Check Tasks
8
Remediate Failures
When control measures fail, owners are notified. Admins create remediation tasks from failed measures. Assigned users complete tasks. Admins re-run tests to verify.
Get Notified Assign Task Complete Task Re-test
⚠️ Key Gotchas
Completing a task ≠ fixing the measure. The task might say "update the policy" but the control measure won't pass until the actual document is updated in the portal.
Editing a requirement affects ALL frameworks. Requirements are shared objects. Changing control measures on one ripples everywhere.
Tests are manual. Admins must click "Run Test" — there's no continuous monitoring. Dashboard data can be stale.
Deactivating ≠ deleting. Deactivated frameworks/requirements retain all data. Purging requires a portal purge code.
🔄 Lifecycle States
Frameworks:
Inactive → Active → Deactivated → Purged
Requirements:
Active → Deactivated → Purged

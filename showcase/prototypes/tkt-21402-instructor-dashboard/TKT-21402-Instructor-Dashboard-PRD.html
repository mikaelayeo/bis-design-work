1Scope

RailPros instructors need to see, during a live classroom exam, which questions the class is getting wrong, which answers people chose and who chose them. Then they can go over a question while people are still taking the exam. This ticket gives the existing Instructor Dashboard (Classroom Calendar → Bookings → Dashboard) a cleaner look and adds one new feature: Results.

Scope rule (Dan, Nov 2): the new look plus the Results list only. Anything today's page doesn't already do is out of this ticket, so it can ship in a couple of weeks. The rest goes to a later ticket, once we have feedback from the clients using the dashboard.

In scope

  • New look for the whole page: header, three panels, course header, Preview, Documents.
  • Participant list with profile pictures and a short status per person.
  • Documents with a coloured icon per type, in grid or list view (as today).
  • Preview and Present, in two screen setups: Extended (laptop plus projector) and Single (one touch screen).
  • Progress window, replacing today's Summary.
  • Results window (new): Most Challenging Questions, Students who need help, and results per course.
  • Manual refresh, as today.
  • Everything today's page already does keeps working (Nov 9, from the dev review): every document type, the slide list, fullscreen, previewing a whole course, forms in Progress and multi-answer questions. See "Kept from today's page".
  • Question Pool questions in Results, using the rules in "Question Pool rules".

Moved to a later ticket ✕ Dropped

  • Overview cards in the left panel (Most challenging question, Students who need help, Finished).
  • Search and sort for participants and documents.
  • Assigning straight from a document card.
  • Results updating on its own every 10 seconds, and the "Update order" prompt.
  • Clicking a name in Results to open Progress.
  • Sort options inside Progress and Results.
  • The "added after courses were assigned" note and per-person Assign (courses already reach everyone).

Out of scope

  • The separate "Course Overview" tab from the original July request (replaced by this one-dashboard design).
  • Assigning PDFs, videos or photos. Only online courses and quizzes can be assigned.
  • PowerPoint conversion or any file-handling changes.
  • Opening the second window on the projector automatically.
  • Grading or messaging tools.

Goals and success measures

  • An instructor can find the most-missed question, and who missed it, in two clicks from the dashboard.
  • An instructor can see who needs help without leaving the classroom session.
  • Ships within RailPros' timeline (about two weeks from Nov 2) with no new back-end features beyond Results.
  • Follow-up: feedback from Astec, RailPros and one other client using the dashboard decides the later ticket.

Question Pool rules

Dev raised this on Nov 6. In a Question Pool, every learner gets their own copy of the pool questions and options, with different IDs, and pool questions can sit in different positions. Results must still show one question with one set of answers. Reuse the logic of the existing Course Answers by Percentage report, which already maps each copy back to its original pool question and matches options by their original position.

Dev questionRule
Grouping answersMap each learner's copy to the original pool question, and each option to its original position, the same way as the existing report. "Two learners chose option C" counts as one option with two names.
Unanswered questions"Not answered yet" lists only learners who were given that question and haven't answered it.
Question listResults lists only questions that at least one learner was given.
Question labelsThe question text with a small "Pool: <name>" tag, and no question number, because its position differs per learner. Hover on the tag explains it.
Random option orderOption letters follow the original (admin) order, not the order the learner saw. The option text is always shown next to the letter.
Pool changed laterResults shows the current pool. If an option a learner chose was removed afterwards, their answer stays counted as wrong under a "Removed" row with the count and names. Edited or reordered options follow the same matching as the existing report (dev to confirm, see Open questions). No other new design in this ticket.

Structure

Anatomy

A DatePicker has a header with month navigation, a 7-column grid of weekday labels and date cells (each cell is a DatePicker Day instance), and an optional sidebar of quick-pick ranges in the Robust variant.

1
Sidebar (Robust only)

Quick-pick ranges: Year to Date, Today, Yesterday, This Week, Last Week, This Month, Last Month, plus a "Last N days/months/years" counter.

2
Header

Previous/next arrows in primary color, month-year label centered. SemiBold 14px.

3
Weekday row

Sun–Sat labels in primary color, SemiBold 12px. Locale-aware via the Language axis.

4
Date grid

7 columns × 5–6 rows of DatePicker Day instances. Each cell is 32×32. The component supports range selection via selected-left/selected-middle/selected-right states.

5
Last counter

In Robust only: "Last [N] days/weeks/months/years" with a number input and unit dropdown.

6
Empty cells

Date cells before the 1st of the month or after the last day use state=empty (32×28, hidden).

Guidance

When to Use

DatePicker is for selecting a date or a date range. Pair with TimePicker if a time is also needed; do not embed time controls inside DatePicker.

✅ Use DatePicker When

  • User picks a date or contiguous date range
  • Range relative to today is common (Robust)
  • The form needs a clear visual anchor for the calendar
  • Designers need range visualization (selected-left/middle/right)

❌ Avoid DatePicker When

  • Date is part of a longer freeform input — use a date Input Field
  • User picks a time only — use TimePicker
  • You need a recurring schedule editor — that's its own component
  • A simple month/year picker is enough — Type=Simple

Specifications

Responsive Behavior New 07/24 Proposed — pending confirmation

The Robust variant's fixed 425px container (150px quick-pick sidebar + 275px calendar pane) overflows narrow viewports — on a 375px screen it clips ~29px past the edge. The fix isn't just reflowing the sidebar: the calendar grid itself needs to go fluid. Two changes proposed for < 600px: (1) collapse the quick-picks into a single full-width dropdown, with a Custom… option that reveals the "Last N" row at the bottom of the card; (2) replace the fixed 32×32 day cells with 7 × 1fr columns at a 44px row height, so the grid spreads to fill the container and stays fluid at any width — matching how native mobile pickers (Material, Google Calendar) lay out. Selected-state colours and shapes are unchanged from web — same primary fill, same continuous-pill range language, just scaled up. Simple variant keeps the same fluid grid treatment; it just has no sidebar to collapse.

≥ 600px — current (unchanged)
Quick-picks stay as a 150px side column, fixed 425×273 container, 32×32 day cells. No change from the existing Robust spec.

↑ resize the window — the grid reflows, it isn't a fixed box

< 600px — proposed (interactive: pick "Custom…" in the dropdown)
Quick-picks collapse into a single full-width dropdown; choosing Custom… reveals the "Last N" row at the bottom of the card. The calendar goes fluid — 7 × 1fr columns with a fixed 44px row height, so days spread evenly to the container width instead of sitting in a 32px grid. Selected styling is identical to web: same surface/primary fill, ranges render as one continuous solid pill with semicircular caps, and a lone day is a solid circle — just scaled from 32px to 44px so it also clears the touch-target minimum.

Touch targets — now compliant

44px day cells clear the 44×44 minimum that the fixed 32×32 desktop cell fails. This removes the "wrap in a 44×44 hit-area" workaround on mobile — the mobile layout satisfies it natively, and the selected circle grows with it so the visual and the hit area finally agree.

Dropdown needs a label

Replacing the quick-pick button group with a select means the existing role="group" aria-label="Quick date ranges" no longer applies — the select needs its own accessible label, and choosing an option should still announce the resulting range via the live region.

⚠️ How "Last N" behaves in the current build (read from PR #117's QuickPickPanel.tsx) — the "Custom…" proposal above is a deliberate change from this:

QuestionWhat the code actually does today
Is there a "Custom" option that reveals the field?No. The "Last N" row renders permanently alongside the quick-pick buttons whenever range mode is on — nothing gates it. The proposal above introduces this gate for mobile.
When does "Last N" apply?Live, on every keystroke. Once a number and unit are both set, each edit re-applies the range immediately and keeps the panel open (keepOpen: true) so you can keep adjusting.
What if I pick "Today", then change the counter to 8?Clicking a quick-pick applies and closes the panel (no keepOpen). The counter's value/unit are local state that reset blank on remount — so reopening gives you empty fields. You can't chain "Today" into "Last 8 days" across a close/reopen; within one open session, whichever control you touched last wins.

That reset-on-reopen behaviour is worth a decision of its own: should the counter remember its last value, and should picking a preset pre-fill it? Flagging for dev on #20416 rather than assuming.

This is a suggested direction, not yet built — flag anything you'd change here before it goes back to dev on #20416.

WCAG Compliance

Accessibility

DatePicker is a complex composite widget. Follow the WAI-ARIA grid pattern for the calendar and treat the sidebar quick-picks as a list of buttons.

Roles

Wrap the date grid with role="grid". Each row uses role="row"; each cell role="gridcell". The currently focused cell has tabindex="0"; all others tabindex="-1".

Keyboard

Arrow keys move within the grid by 1 day / 1 week. PageUp / PageDown move by month. Shift+PageUp / Shift+PageDown move by year. Home / End go to start / end of week. Enter / Space select. Esc closes the picker.

Selection state

Selected dates use aria-selected="true". Range visualization (selected-left/middle/right) is purely visual — keep aria-selected on every cell in the range.

Labelling

Each date cell needs an aria-label with the full date (e.g., "September 15, 2024, Sunday") — the visible text is just the day number, which screen readers can't disambiguate.

Quick-picks (Robust)

Sidebar items are buttons. Wrap in a role="group" with an accessible label like "Quick date ranges". Each pick triggers an immediate range selection — announce the new range via a live region.

Color contrast

Selected cells (#fff on #0078b3) hit 4.6:1 (AA). Disabled / out-of-month cells must still meet 3:1 against the background or include a non-color indicator (italic, lower-opacity).

Touch targets

32×32 cells are below the 44×44 mobile minimum. On touch surfaces, increase cell size to 44×44 or wrap in a 44×44 hit-area while keeping the visual at 32.

Locale

Use the Language variant to set weekday and quick-pick labels. Date format in aria-label should also be localized.

Code Examples

Single date (Simple)

React / TSX
const [date, setDate] = useState<Date>(new Date());

<DatePicker
  type="Simple"
  language="English"
  value={date}
  onChange={setDate}
  aria-label="Birth date"
/>

Date range (Robust)

React / TSX
const [range, setRange] = useState<[Date, Date]>([
  startOfMonth(new Date()),
  new Date()
]);

<DatePicker
  type="Robust"
  language="English"
  range
  value={range}
  onChange={setRange}
  aria-label="Report date range"
/>

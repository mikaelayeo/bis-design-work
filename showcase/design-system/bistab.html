Structure

Anatomy

A BisTab is a horizontal row of tab items. Each row may also contain a more overflow indicator (when tabs exceed available width) and an add button (when users can create new tabs). The label is the only mandatory part.

1
Selected Tab

Active tab — distinct color, weight, or indicator (varies by type). Only one tab can be selected at a time.

2
Deselected Tab

Inactive tabs use secondary text color. Clicking them activates them and deselects the previous tab.

3
More (overflow)

Optional. Appears when tabs exceed available width. Italic style, primary color when expanded.

4
Add

Optional. Plus icon to create a new tab. When clicked, transforms into an inline "New Tab" input.

Guidance

When to Use

Tabs let users switch between sibling views of related content without leaving the page. Pick the type based on visual weight required — heavier types for primary navigation, lighter for in-content section toggles.

✅ Use BisTab When

  • Switching between sibling views of equal hierarchy
  • Content fits in 2–7 distinct sections
  • Users benefit from seeing all section labels at once
  • State should be preserved when switching between sections
  • Sections share a parent context (settings, profile, report)

❌ Avoid BisTab When

  • Sections should appear in a specific order (use steps)
  • There are more than 7 sections (use side nav or dropdown)
  • Sections have a parent-child relationship (use breadcrumbs)
  • The content is a list of filterable items (use Chip)
  • Users only see one section per visit (use Page links)

WCAG Compliance

Accessibility

BisTab is an interactive navigation pattern. It must follow the WAI-ARIA tabs pattern with full keyboard support and meet WCAG 2.1 AA contrast requirements.

Roles

Wrap tabs in role="tablist". Each tab uses role="tab" with aria-selected and an associated aria-controls pointing to its panel.

Keyboard

Tab moves focus into and out of the tablist. Left/Right arrows move between tabs. Home/End jump to first/last tab. Enter/Space activates a tab. Use a roving tabindex.

Focus

Visible 2px focus outline in primary color, 2px offset from the tab edge. Focus indicator must reach 3:1 contrast against the surface behind the tab.

Color Alone

Floating type relies heavily on color + border. Pair with a weight or underline change if used at small sizes. The 3px underline in Expanded/Simple gives non-color reinforcement of selection.

Add Button

The "+" button needs aria-label="Add tab". When it transforms into the input, focus moves to the input and the input has its own label ("New tab name").

More Overflow

"1 more..." should be a button that opens a menu listing the hidden tabs. Use aria-haspopup="menu" and aria-expanded.

Contrast

Secondary text (#666 on #feffff) passes AA at 5.7:1. Selected primary (#0078b3) passes AA at 4.6:1. Verify the 3px underline indicator against the actual page background — light grays may fail 3:1.

Touch Targets

Minimum 44×44px tap area on touch surfaces. Traditional and Simple types meet this with default padding. Floating may need extra hit padding on mobile.

TypeScript Interface

TypeScript
type BisTabType = "traditional" | "floating" | "expanded" | "simple";

interface BisTabProps {
  type?: BisTabType;            // default: "simple"
  value: string;               // id of selected tab
  onChange: (value: string) => void;
  onAdd?: (label: string) => void;
  overflow?: "hide" | "menu"; // default: "menu"
  ariaLabel: string;
  className?: string;
  children: ReactElement<BisTabItemProps>[];
}

interface BisTabItemProps {
  id: string;                  // required, unique within row
  label: string;
  disabled?: boolean;
  badge?: number | string;
}

Tabs with Add & Overflow

React / TSX
const [tabs, setTabs] = useState([
  { id: "sheet-1", label: "Q1 Report" },
  { id: "sheet-2", label: "Q2 Report" },
]);
const [active, setActive] = useState("sheet-1");

const handleAdd = (label: string) => {
  const id = `sheet-${tabs.length + 1}`;
  setTabs([...tabs, { id, label }]);
  setActive(id);
};

<BisTab
  type="floating"
  value={active}
  onChange={setActive}
  onAdd={handleAdd}
  overflow="menu"
  ariaLabel="Report sheets"
>
  {tabs.map(t => (
    <BisTabItem key={t.id} id={t.id} label={t.label} />
  ))}
</BisTab>

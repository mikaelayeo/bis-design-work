Design Decisions

  • Format selector placed as a per-column sub-control inside Customized Columns, consistent with the ticket's proposed solution. Flagged as open question below.
  • Radio group used for the two format options (not a dropdown) because two choices are better expressed as always-visible radio buttons. Revisit if additional formats are added.
  • The "Entered By First Name" and "Entered By Last Name" fields remain as two separate columns in the picker. The format setting controls how values render in each column, not whether they are merged. Merging into a single "Entered By" combined column is a separate open question.
  • Preview table reflects current selected state (First Last default). Interactive state swap not implemented in this Level 1 artifact.
  • Callout help text is placed directly inside the sub-panel so it is contextually tied to the setting, not buried in a global help section.
  • Layout: report shell uses a fixed-width column-picker with two panes and center arrow controls — mirrors the existing Advanced Form Reporting UI pattern as described.

Open Questions

  • Q1 (scope): Should the format setting live per-column inside Customized Columns (this wireframe's approach), or as a user/account-level preference? Per-column gives report-specific control but adds friction if Athabasca always wants the same format everywhere.
  • Q2 (default): For existing saved reports that have these columns, what is the default on first deploy — preserve whatever is currently rendering, or force "First Last"? Impacts whether Athabasca needs to re-save all their scheduled reports.
  • Q3 (field scope): Does the format selector apply only to "Entered By" name fields, or should it also appear for "Reviewed By", "Assigned To", and other name fields? Ticket implies Entered By only — confirm with Aswin / Christina before expanding.
  • Q4 (column merge): Should "Entered By First Name" and "Entered By Last Name" stay as two separate columns (current model, wireframed here), or offer a merged "Entered By" single column with the format selector controlling the combined output? The merged approach may be cleaner for PowerBI ingestion.

A. The Problem and How the PDF Template Works Reused pattern

The problem: every portal's ID badge has the same BIS-generated layout, controlled only by on/off toggles. Excelsior needs their own branded layout, the option to leave the profile photo off, and freedom to place and size the QR code, logo, text and photo. The solution: admins upload a PDF template, exactly like the Adobe Embedded certificate templates on TRM Edit Course. There is no visual editor — agreed dev scope is "upload your own PDF with any fields we currently support in ID badges, and we print badges from it." Badges are still downloaded from each user's profile; that flow doesn't change.

1 Design the badge artwork
In any design tool. Logo, colours and layout are simply part of the PDF — export as PDF.
2 Open in Adobe Acrobat → Prepare Form
Draw one text field per data item (name, role, employee ID…). Name each field exactly as listed in section G, e.g. FullName.
3 Use "Add an image" for pictures
Profile photo and QR code are image fields. Skip the photo box and no photo prints — this covers the "photo optional" request.
4 Upload it in the Custom ID Badge card
Upload, check it with Test Badge, then turn the toggle on (sections B–E).
⚠
Watch-out: a misspelled field name is silently left blank. That is why the PDF ID Badge Guide, the optional starter template and the Test Badge button all matter.
Confirmed: one PDF template per portal; any badge data without a matching field in the PDF is simply not printed; any field with no data is left blank. The full field-name list is in section G.
B. The Custom ID Badge Card — First in the Grid, Before a Template Exists New cardReused uploaderStarter PDF

The ID Badges grid stays exactly as it is today. The only addition is one new card, placed first — top of column 1, above Lock Profile Image, with the existing cards flowing beside and below it exactly as they do now. It is built like every other card: toggle, bold label, collapse chevron, grey italic info strip. With no template yet, its toggle is disabled, and hovering it explains why. Clicking the toggle (or the header) expands the card so the Upload button is right there — the disabled toggle doubles as a pointer to the uploader. Until a template is uploaded and the toggle is on, every other card works as normal.

C. Template Uploaded — Toggle Enabled, Still Off Reused uploaderNew file rowTest Badge

Uploading is decoupled from turning it on. After upload, a bordered file box replaces the Upload button and the toggle becomes enabled — but nothing changes for users until it is switched on, and every other ID badge setting stays fully active. This gives admins a safe "draft" without a draft concept. The Test Badge button is the check step: it lets Excelsior see the template working before going live, as they asked.

D. Confirm and Success Modals BisModalModalService.successNew copy

Turning the toggle on is the real "go live" moment — and it disables the layout settings — so it asks for confirmation. Turning it off is just as easy and gets its own confirm, so a misclick on either side is recoverable. Once an action completes, a success message confirms it.

E. Custom On — Layout Settings Disabled New stateReused cardsDev to confirm

With the toggle on, the 10 layout settings are disabled — not hidden. They stay in place at about 50% opacity, their toggles, radios and uploader not clickable, and their saved values untouched. Admins can still see what is set, and nothing on the page reflows. Hovering (or keyboard-focusing) a disabled card shows a dark tooltip. ID Badge Back Panel and Folder Document and Forms stay fully enabled — they aren't layout, so they still apply. The Custom ID Badge card stays fully live, including Test Badge and Remove.

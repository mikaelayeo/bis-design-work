Design specification for PM & Development
AskAmy Live Chat · TKT-19627 · March 2026
Key Principle

The snackbar is the interrupt; the tab badges are the source of truth. If an agent misses a snackbar, the segmented control badges on "My Chat" and "Unclaimed" tabs always reflect the current state.

Section 3

Scenario: Multiple Notifications

When new notifications arrive while one is already displayed. The system uses a sequential queue — only one snackbar is visible at a time.

Core Rule: One Per Type, Stacked When Both Arrive

Each notification type shows one snackbar at a time. If both a "New chat request" and a "New reply" arrive in the same period, they stack vertically — "New chat request" is always on top (higher priority). Each type manages its own queue with its own counter badge.

Section 4

Interaction During Queue

What happens when the agent clicks a CTA while other notifications are queued.

Current snackbar closes immediately. The agent acted on it — no need to wait for the timer.

The corresponding action executes. Chat panel opens (for "Open chat") or chat is claimed and panel opens (for "Claim").

2-second pause before the next notification. The agent is now orienting themselves in the chat they just opened. A snackbar sliding in instantly would be disruptive.

Next queued notification slides in with its own fresh timer. Counter updates accordingly.

Why the 2-Second Delay?

When the agent clicks "Open chat," a chat panel opens. They need a moment to read context and orient themselves before the next notification asks for their attention. This buffer prevents the feeling of being overwhelmed.

Why Not Dismiss the Entire Queue?

Clicking "Open chat" on a reply doesn't mean the agent has seen or decided about the unclaimed chat request sitting in the queue. Those are different notification types requiring different decisions. Clicking on one doesn't acknowledge the others.

The Full Flow

Agent clicks "Open chat" on reply snackbar
→ reply snackbar closes
→ chat panel opens
→ 2-second pause
→ next reply notification slides into bottom position
→ its own timer starts
→ chat request snackbar (if present) is unaffected — stays in top position
→ same pattern continues until that type's queue is empty

Dismissing Without Action (× button)

If the agent clicks × without taking action:

Snackbar closes immediately.

Next notification slides in with no delay (agent chose to dismiss — they're ready).

The dismissed item is NOT lost — the tab badge still reflects it.

Section 5

Stacking Model: Two Lanes

Each notification type has its own lane. When both types are active, they stack vertically.

Top position: New chat request

Higher priority. Always stacks above if both appear. Has its own queue and counter for additional chat requests.

Bottom position: New reply

Lower priority. Stacks below chat requests. Has its own queue and counter for additional replies.

How it works

Each lane shows one snackbar at a time for its type. Within each lane, additional notifications of the same type queue up with a counter ("+N other notifications"). Clicking the counter opens the dashboard showing those chats. If only one type is active, its snackbar appears alone — no stacking needed.

Section 6

Sound Notifications

Sound plays on arrival, not when displayed from queue.

If 3 notifications arrive in 5 seconds → 3 sounds at their arrival times.

Reply and request use different sounds so agents can distinguish by ear.

Sound only plays for agents marked Online.

Section 7

Edge Cases

Agent is Offline

Offline agents do not receive snackbar notifications for new chat requests. However, if an offline agent has manually claimed a chat, they still receive reply notifications for that claimed chat.

Chat Claimed by Another Agent

If Agent A sees a "New chat request" snackbar and another agent claims it first:

Recommended: Auto-dismiss

The snackbar closes immediately. Next queued notification slides in. The "Unclaimed" tab badge decrements.

Browser Tab Not Focused

When the agent's browser tab is not in focus, the snackbar queue pauses. When they return, the current snackbar appears with a fresh timer. Additionally, the browser's native notification API fires an OS-level notification so the agent is alerted even when working elsewhere.

Queue Overflow (10+)

If the queue reaches 10+ notifications, cap at 10 and stop adding. Counter shows "9+ other notifications." Tab badges always show the true count. At this volume, the dashboard table is the better triage interface.

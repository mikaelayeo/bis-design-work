How it wires (for Jithin)

The reports form is data-driven — FilterFactory.js renders rows from tblReportParameters by parameterType. A ToggleOptions (parameterType 6) row already renders as a single-select highlighted list and stores one value via item.toggleOptionOn, so this is config + backend, no new React component needed.

  • Add one parameter row for the Training Matrix High-Level Summary report: 
    parameterType: 6            // ToggleOptions → single-select list
uniqueIdentifier: "displayformat"
headerLabel: "lblReportsDisplayFormat"
displayColumnNo: 2          // right column, beside Location (per Figma)
options: [
  { headerLabel: "Percentage (e.g. 25%)",        toggleOptionOn: 0 },  // default = options[0]
  { headerLabel: "Raw numbers (e.g. 10 out of 40)", toggleOptionOn: 1 }
]
  • Frontend: reuses SyncMultipleSelect (isToggle). One small visual tweak vs. today's component — Mika's design shows a radio on each row instead of the current fa-check on the active row. Swap the check glyph for a radio in that component (or a variant).
  • Tooltip: the ⓘ helper uses the existing react-tooltip already imported in FilterFactory.js — text in lblReportsDisplayFormatTooltip.
  • Backend (bisadmin.RunReport / generate): when displayformat == 1, render each compliance cell as completed / assigned instead of the percentage. Both numbers already exist (% is completed ÷ assigned).
Note: today's ToggleOptions list marks the active row with a checkmark; this design uses a radio button. Functionally identical (single-select) — purely the selected-row affordance.

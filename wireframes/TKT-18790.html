Fidelity

  • Level 1 — Minimal Wireframe. No design system tokens applied. Structure and component references only.

Design Decisions

  • Direction followed exactly as specified in ticket: Value field converted to multi-select checkbox list; Field remains single-select.
  • Layout: Two-column "Today vs Proposed" comparison. Both columns show the full Create Metric panel at the same level of detail so changes are directly diffable.
  • Multi-select pattern references the Forms module bulk-select (checkbox list + selected count) and the Training Matrix multi-row select. These are existing BIS patterns — no new affordance invented.
  • Component slot for Value: BisListBox (multi-select variant). Search input at top of list follows existing BIS combobox/listbox pattern.
  • Component slot for primary button: BisButton (primary). Label update ("+ Create N Metrics") is a text/count binding only — no new component needed.
  • Preview block ("This will create N metric datapoints") placed between the metric card and the CTA button. Communicates bulk consequence before commit. Styled as an informational inset — analogous to BIS confirmation callout pattern.
  • Name field: annotated as base template in the proposed state. Auto-suffix pattern: "{base} – {value}". Flagged as open question (designer/PO to confirm).
  • Colour field: unchanged in wireframe. Whether N metrics share one colour or get auto-assigned is an open question.
  • The +/- buttons next to Field are preserved unchanged in both states. Their exact current behavior is unverified and flagged.
  • Preview block only renders when count is greater than 1. Single-selection falls back to current single-metric behavior (button reads "+ Create Metric").

Open Questions

  • Should "apply to all selected values" be the default behavior (as wireframed), or should there be a separate "Bulk Mode" toggle the user enables first? Toggled entry may reduce accidental bulk creates.
  • Name field behavior: is auto-template ("{base} – {value}") the right default, or does the user want to set one shared name and handle naming themselves after creation? Confirm with Chaahat.
  • Does Field also need multi-select in a future phase? Chaahat's use case description ("same metric in multiple departments") implies Value is the key axis, but verify.
  • What do the +/- buttons next to Field do today? Must verify in the live environment before deciding whether to repurpose or remove them when multi-select is active. URL: https://www.bissafety.app/analytics/d/_6F9864F365E0B68927451D0989B57D22
  • Colour assignment when creating N metrics at once: same colour for all (as wireframed), or auto-assign from a palette? Auto-assign adds complexity but produces a more usable dashboard. PO call.
  • Edge case: what is the upper bound on selected values? If a user selects 50 values, 50 widgets are created at once. Is there a hard cap, a confirmation step, or a warning threshold?

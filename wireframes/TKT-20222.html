Design Decisions

  • Legend container: changed from flex-wrap: nowrap to flex-wrap: wrap — chips reflow to the next row automatically when horizontal space is exhausted. No JavaScript required.
  • Legend chip text: changed from white-space: nowrap; overflow: hidden; text-overflow: ellipsis to white-space: normal; max-width: 140px so full labels remain readable inside the chip per Chaahat Arora's comment.
  • Widget title: removed the fixed single-line height cap and added overflow-wrap: break-word so count box titles wrap to a second line rather than clipping when the container is narrow.
  • Date range → calendar icon button: the inline date range string is replaced with a single calendar icon (BisButton / Icon / Ghost). This applies everywhere the date currently competes for header space — widget headers and filter chips.
  • Hover tooltip on calendar icon: hovering or focusing the icon reveals the current date range in a small tooltip (read-only view). Clicking opens the existing date range picker for editing. This separates "see the date" (cheap, always available) from "change the date" (one click away).
  • Long-widget-name scenario: by collapsing the date to an icon, long widget/filter titles like "C1-3 Shipping and Receiving Audit" can show in full instead of being truncated to make room for the date string.
  • No production colours, spacing tokens, or typography tokens applied — those are reserved for Level 2 Styled Mockup. Filter chip uses a placeholder warm gray; production should use the existing orange filter-chip token.

Open Questions

  • Should the wrapping legend chip stay a fixed single-line pill height, or is a taller multi-line pill acceptable? A tall pill may feel visually heavy.
  • Is there a max number of legend rows (e.g. 3) before a "Show more / Show less" toggle is needed, or should all rows always be expanded?
  • Calendar icon click behaviour: inline date picker on desktop, BottomSheet on mobile? Confirm the icon-only treatment is acceptable on desktop too (no visible date string at rest, only on hover).
  • Tooltip dismissal: hover-out is the default. On touch devices (no hover), should tap-once show the tooltip and tap-again open the picker, or should tap always go straight to the picker?
  • Filter chip scenario: should the calendar icon also appear in the filter-chip context, or only in widget headers? The wireframe applies the same pattern to both for consistency — confirm this is desired.
  • Figma file key not available — which Figma file holds Reporting Dashboard components? Names (LegendChip, CountWidget, FilterChip, etc.) need verification before Level 2 / dev handoff.

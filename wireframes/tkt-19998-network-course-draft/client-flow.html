Change markers:
  • Playlist elements — pill in the existing Status column ("Edited" / "New" / "Deleted"). Reuses the same column as today's "Approved" / "Pending" — no new UI region.
  • Tab labels — "edited" pill next to each tab that contains changes, so the client (and Amanda later) can see at a glance which tabs are affected.
  • Section/element headers (slide editor, E-Commerce sections, Configure form, Notification templates) — "(Edited)" badge next to the header title. Not shown here; pattern is consistent across all tabs.
  • Markers stay persistent across submit → return → re-edit cycles.
Action paths:
  • Clicks Submit for Review → Screen 6 (submit confirmation modal).
  • Clicks Save Draft → toast confirmation, stays in edit mode. Navigating back to the course list now shows the Draft badge → Screen 5.
  • Clicks Discard Draft → confirmation modal → returns to view mode (Screen 2) with no changes saved.

What's new: after the client clicks Save Draft in edit mode (Screen 3 / Screen 4), the network course in the course list shows a "Draft" badge in the Status column. This is how the client knows there's work in progress they can come back to.
Behavior: clicking the row with a Draft badge skips view mode and reopens the course directly in edit mode — the client picks up exactly where they left off. Inline change markers and the unsaved-changes state are preserved.
Other status states that appear here: when the client submits, the badge flips to "Pending Review." Once approved, it returns to "Active." Path B drafts (Amanda direct edit) are not visible to the client — the row stays "Active" from their side.
Open question (design): if a Path B draft is in progress on the same course, should the client see a "Locked by BIS" indicator instead of "Active" to explain why they can't open it? Discuss with Amanda + QA.

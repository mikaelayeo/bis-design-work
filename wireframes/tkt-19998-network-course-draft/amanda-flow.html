What changed from the previous draft of this concept review: Path B now has the same draft affordance as Path A. Amanda doesn't have to commit immediately — she can save in-progress work and come back, or discard if she changes her mind.
Three actions in the header:
  • Discard Draft — confirmation modal → throws away all of Amanda's WIP, course reverts to live state.
  • Save as Draft — keeps Amanda's changes in a private draft on the live course. No client notification yet. Amanda can return and continue editing.
  • Push to Store — commits the changes live. Client receives the "changes made" email automatically (same as before).
Open questions this raises:
  • @QA: If Amanda has a Path B draft saved and the client tries to start a Path A draft on the same course — what happens? Probably block the client's Path A entry with a message ("BIS is currently editing this course — try again later") since Path B drafts are invisible to the client.
  • @Luke: Path B drafts need to live separately from Path A drafts in the data model. Confirming one course can hold at most one of each, never both editable at the same time.
  • @Amanda: Should Path B drafts have an expiry / reminder if left untouched (e.g., 14 days)? Reduces risk of stale drafts blocking client edits indefinitely.

IDEA 1

AI ideation pipeline

Lead: Mika

Claude generates HTML prototypes from ticket scope, cutting time on smaller tickets and enabling non-designers to self-serve. The pipeline: BIS PM MCP / Fellow MCP → Claude → HTML prototype → review → fast-track to dev or deeper design work.

Apr 17-21 Set up the studio Mika + Claude
  • Create a new Claude Project: "AI Ideation Pipeline"
  • Draft project instructions (Claude writes first pass, Mika refines)
  • Connect MCPs: BIS PM, Figma, Notion
  • Upload 3-5 sample HTML prototypes as knowledge files
  • Upload design system reference (tokens, component patterns)
Deliverable: A working Claude Project that both Mika and Mahi can access with everything pre-loaded.
Apr 24-28 Mika runs the pipeline solo Mika solo
  • Pick 5 real tickets of varying complexity from the backlog
  • Run each through the pipeline: ticket → Claude → HTML prototype
  • Log what works and what breaks (prompt quality, output quality, missing context)
  • Refine the project instructions based on findings
  • Draft initial "ready for dev" vs "needs design" criteria from real examples
Deliverable: 5 prototype examples + refined prompt template + first draft of decision criteria.

Checkpoint: is this worth continuing?

If 3+ of the 5 tickets produced usable prototypes, proceed. If not, revisit the prompt or scope before expanding.

Apr 29 – May 2 Cross-test with Mahi Mika + Mahi
  • Mahi tests Mika's pipeline with 5 new tickets independently
  • Compare results — where did the pipeline behave differently?
  • Identify gaps: does the prompt assume knowledge only Mika has?

  • Solidify the decision criteria into a checklist
Deliverable: 10 total prototypes, validated prompt template, decision checklist that works for both designers.

  • Invite Aymeric into the Claude Project (or build a simplified interface)

  • Decide: does the "others" path need a simpler interface or guardrails?
Deliverable: Clear answer on whether the "others" path works, and what it needs to scale.

  • Quantify time saved per ticket vs Toggl baseline data

IDEA 2

AI-enhanced design-to-dev handoff

Lead: Mahi

A two-sided handoff protocol (design checklist + dev acknowledgment) enhanced by AI-generated handoff packages — screenshots, specs, Storybook component recipes, starter code, and implementation notes. Kills the "limbo" problem where tickets sit between design and dev.

Apr 17-21 Build the checklist + component mapping Mahi + Mika
  • Draft the design-side handoff checklist (Figma deliverables, specs, context)
  • Draft the dev-side review acknowledgment checklist
  • Create component mapping spreadsheet: Figma component name → Storybook story path → import statement
  • Map your top 20-30 most-used components to start
  • Define ticket statuses: "Ready for dev review" → "In development"
Deliverable: Design-side + dev-side checklists, component mapping spreadsheet.
Apr 24-28 Mahi tests AI handoff packages Mahi solo
  • Pick 3 real tickets that are ready for handoff (or recently handed off)
  • Generate AI handoff packages using Figma MCP + BIS PM MCP + mapping spreadsheet
  • Evaluate output quality: are specs accurate? Is the component recipe correct? Is the starter code useful?
  • Log component mapping accuracy — how often does Claude get the right Storybook component?
  • Refine the handoff package format based on findings
Deliverable: 3 handoff package examples + accuracy log + refined package template.
Apr 29 – May 2 Cross-test with Mika Mahi + Mika
  • Mika tests Mahi's handoff pipeline with 3 new tickets
  • Compare outputs — is the checklist clear? Does the AI package vary in quality?
  • Identify what's missing: edge cases, design system gaps, unclear notes
  • Refine checklists and package format together
Deliverable: 6 total handoff packages, refined checklists validated by both designers.
May 5-8 Devs receive real handoff packages Mahi + Aymeric, Vishnu C.S., or Jon
  • Give 2-3 devs actual AI-generated handoff packages for real tickets
  • Ask: Is this useful? What's missing? Would you use the Storybook links?
  • Test the dev-side acknowledgment checklist — does the handshake work?
  • Track: did the ticket move faster with this process vs. the old way?
  • Document component mapping accuracy rate (for Code Connect pitch)
Deliverable: Dev feedback, mapping accuracy data, handoff speed comparison.
May 12-22 Compile results for presentation Mahi + Mika
  • Compile dev feedback and mapping accuracy rate
  • Document "before vs after" handoff experience
  • Build the Code Connect pitch with real data
  • Feed findings into final leadership presentation

Upload Ask Amy knowledge base docs so Claude designs with full system context. No deep dives needed. Upgrade to live feed when AI lead ships automated documentation sweep. Piggybacks on idea #1 setup — no separate timeline needed.

  • Upload top 15-20 most design-relevant KB docs to the Claude Project
  • Prioritize: user roles, asset categories, admin views, forms, troubleshooting, course builder
Deliverable: KB docs uploaded to the Claude Project alongside idea #1 setup.
Apr 24 – May 2 Use passively during testing Mika + Mahi

  • Log when KB context helped Claude produce better designs
  • Log when KB context was missing, outdated, or incomplete
May 5-8 Tally results + check future path Mika

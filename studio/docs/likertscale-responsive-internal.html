Likert Scale — Responsive layout rules

How the rating widget should switch between the table and card layouts across phone and tablet. Companion to the client preview (which shows only the layouts, no rules). Token/spec hand-off is at the bottom.

Recommendation

Switch on available width, not device model. Render cards when the widget's available width is under 600 dp; render the table at 600 dp and above.

This maps cleanly onto the flags the component already has: 600 is the same threshold as isTypeTablet = Math.min(width,height) >= 600 in theme/sizes/spacing.ts. In practice: phones get cards, tablets get the table in both orientations.

What we learned from Microsoft Forms

MS Forms only renders its card layout on narrow portrait viewports (portrait phone, portrait iPad mini) and falls back to the matrix/table on anything wider. The takeaway isn't the exact device list — it's the principle:

  • Width decides, not device. A single breakpoint is simpler and more robust than enumerating models.
  • Cards are the narrow-screen fallback, not a replacement. The table stays the default wherever it fits.
  • One difference for BIS: MS shows cards on iPad mini portrait; we don't need to. At 768 dp the table fits all four columns cleanly, so a 600 dp breakpoint keeps tablet portrait on the table. (If product wants the MS parity feel, raise the breakpoint to ~768 — noted as an option, not the recommendation.)
  • We have fewer cases to handle: no phone-landscape state, so the only switch is phone-portrait ↔ tablet.

Implementation note

  • Drive the switch off the measured container width (or useWindowDimensions) against the 600 threshold; re-evaluate on rotation so tablets flip correctly.
  • The current renderInlineGrid path already covers the narrow case conceptually — the change is to render cards below the breakpoint instead of the horizontally-scrolling grid, and the standard table above it.
  • Many options (6+): even on tablet the table can get tight — keep the card fallback available if columns > a sensible max, regardless of width.

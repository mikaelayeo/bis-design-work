Structure

Anatomy

A Select has two parts — the trigger field visible in forms, and the menu panel that floats below when opened. Each part has well-defined sub-elements.

1
Label

Optional. 16px Segoe UI Semibold. Use sentence case. Required indicator is the red asterisk next to it.

2
Trigger Field

32px tall. 4px corner radius. Shows current value or placeholder. Border indicates state (default, focus, error, etc.).

3
Trailing Affordance

Chevron-down by default. Replaced by ✕ clear button when user is typing in a Combobox.

4
Helper Text

Optional. 12px Segoe UI Regular. Use for hints. Becomes red error message when state is error.

5
Menu Panel

Floating panel attached 4px below trigger. White surface, 1px gray border, soft shadow, 4px radius. Hosts options and special states.

6
Selected Indicator

Leading ✓ checkmark + primary text color marks the active selection. No heavy background — modern, accessible.

Guidance

When to Use

Pick Select for short stable lists. Pick Combobox when typing is faster than scrolling.

✅ Use Select When

  • 2–10 stable, named options
  • Selection is mutually exclusive (single value)
  • Users recognize the options at a glance
  • The list rarely changes

✅ Use Combobox When

  • 10+ options or unbounded list (e.g. user search)
  • Typing is faster than scanning visually
  • Partial-match filter is helpful
  • Free-text fallback is acceptable

❌ Avoid Both When

  • Only 2–3 options visible always (use Radio or SegmentedButtons)
  • User needs to compare options side-by-side
  • Users select multiple values (use a multi-select component instead — v2 backlog)
  • The action is irreversible or destructive (use Button + Confirm)

❌ Don't Use Combobox When

  • The list of options is short (Combobox typeahead adds cognitive load)
  • Users won't know the names ahead of time (browse-only)
  • The platform doesn't support filtering reliably (e.g. ancient browsers)

Accessibility

Selects must be reachable and operable via keyboard alone, and announced clearly to screen readers.

ARIA roles

Trigger uses role="combobox" with aria-expanded, aria-controls pointing to the menu panel, and aria-haspopup="listbox". Menu uses role="listbox" and items use role="option" with aria-selected.

Required field

When required is true, set aria-required="true". The visible asterisk is decorative — screen readers should hear "required" via the attribute, not the asterisk character.

Keyboard navigation

Tab focuses trigger. Space / Enter / ↓ opens menu. ↑ / ↓ moves between options. Enter selects. Esc closes. Combobox: typing filters. Maintain aria-activedescendant on the trigger pointing to the currently focused option.

Focus indicator

Trigger uses 1px primary border on focus. Menu items show a 1px primary outline (inset). Both meet 3:1 contrast against their backgrounds.

Color independence

Selected state uses both color (primary) AND a leading ✓ checkmark. Error state uses both red border AND a red helper message. Never rely on color alone.

Touch targets

Menu items are 40px tall — meets 44×44 minimum once horizontal padding is included. Trigger is 32px tall, so ensure there's vertical breathing room (label + helper) so the entire labelled control is at least 44px.

HTML — Accessibility template
<!-- Combobox trigger -->
<div>
  <label id="sel-label">User</label>
  <input role="combobox" aria-expanded="false"
         aria-controls="sel-listbox" aria-haspopup="listbox"
         aria-labelledby="sel-label" aria-required="true" />
</div>

<!-- Menu -->
<ul id="sel-listbox" role="listbox">
  <li role="option" aria-selected="true">Option 1</li>
  <li role="option" aria-selected="false">Option 2</li>
</ul>

Implementation

Code Examples

Reference implementations using the BIS Common Components React library.

Basic Select

React / TSX
const [reportType, setReportType] = useState<string | null>(null);

<BisSelect
  label="Report type"
  required
  options={[
    { id: "asset",    label: "Asset Summary Report" },
    { id: "billable", label: "Billable User Report" },
    { id: "cert",     label: "Certification Program Report" },
  ]}
  value={reportType}
  onChange={setReportType}
/>

Combobox with async search

React / TSX
const [query, setQuery]   = useState("");
const [users, setUsers]   = useState<User[]>([]);
const [loading, setLoading] = useState(false);

useEffect(() => {
  if (!query) return;
  setLoading(true);
  fetchUsers(query).then(setUsers).finally(() => setLoading(false));
}, [query]);

<BisSelect
  type="combobox"
  label="User"
  options={users.map(u => ({ id: u.id, label: u.fullName }))}
  loading={loading}
  onSearch={setQuery}
  onChange={handleSelectUser}
/>
